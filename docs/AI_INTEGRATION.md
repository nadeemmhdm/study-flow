# AI Integration

Study Flow generates learning branches from an AI provider instead of a hard-coded curriculum.

## Tree model

The topic entered by the learner is always the root node. The optional description is displayed as root context. The requested 1–10 child branches are generated by the configured AI model and are not selected from a built-in stage list.

## Provider configuration

Open **Settings** in the web interface and configure:

- API Base URL — an OpenAI-compatible API base ending at the version root, for example a provider's `/v1` base.
- Model — the provider-specific model identifier.
- API Key — bearer credential when the endpoint requires one.

Use **Test connection** before generating a flow.

## Credential handling

The API key is stored only in browser `sessionStorage`. It is not written to Study Flow history, plan exports, source files or localStorage. Closing the browser tab/session clears normal session storage.

Because Study Flow is a browser application, requests are sent directly from the browser to the configured provider. The provider must permit browser CORS requests. For production/shared deployments, a server-side credential proxy is recommended instead of distributing a private API key to browsers.

## AI response contract

Study Flow asks the provider for strict JSON containing exactly the requested number of subtopics. Each subtopic contains a title, summary, objectives, practice task and research query. Invalid responses are rejected rather than silently replaced with hard-coded lessons.

## Privacy

Topic text and the optional description are sent to the configured AI provider when **Build with AI** is selected. Users should review their provider's data policy before sending sensitive material.


## Provider presets

The Settings interface includes provider presets so users normally do not need to know endpoint or model identifiers.

| Provider | Authentication | Default behavior |
|---|---|---|
| OpenAI | API key | Uses the built-in OpenAI endpoint and default model |
| Groq Cloud | API key | Uses the built-in Groq OpenAI-compatible endpoint and default model |
| OpenRouter Cloud | API key | Uses the built-in OpenRouter endpoint and default model |
| Ollama Cloud | Ollama API key | Uses the direct Ollama Cloud OpenAI-compatible API (`https://ollama.com/v1`) and a cloud model |
| Custom AI Provider | Provider-dependent | User supplies endpoint, model and optional API key |

Preset providers expose a **custom model** option. When disabled, Study Flow uses its maintained default model identifier. When enabled, the user can enter another model supported by that provider.

Custom providers must expose an OpenAI-compatible `/chat/completions` API and permit browser CORS requests.
